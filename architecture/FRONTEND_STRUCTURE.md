# Frontend Structure

- `frontend/src/views/*.vue` — one per route, wired in `frontend/src/router/index.ts`: `DashboardView`, `AccountsView` (cards + stat cards + embedded `TransactionsPanel`), `AccountsManageView`, `SpendingView`, `RulesView`, `CategoriesView`, `InboxView`, `ProfileView`, `LoginView`, `SignupView`, `UiKitView`. Rules, categories and spending are sub-routes under `/accounts`; settings lives in the user popup (`/settings`).
- `frontend/src/components/` — shared UI: `AppLayout` (sidebar shell), `AppModal`, `Popover`, `ConfirmDialog` (replaces native `confirm()`), `AppInput` / `AppSelect` (labeled form controls — never hand-roll input/select class strings), `Pagination`, `DatePicker`, `AccountCard`, `StatCard`.
- `frontend/src/components/workspace/` — transactions/rules workspace components (`TransactionsPanel`, `TransactionsTab`, `TransactionTable`, `AddTransactionModal`, `EditItemModal`, `TransferModal`, `RuleForm`, `RulesTab`, `CategoriesTab`, `CategoryForm`, `TransactionForm`).
- `frontend/src/lib/utils/` — pure helpers (formatting, filters, rule outputs, category colors) factored out of views; each has a co-located `*.test.ts` under vitest.
- **UI conventions on every UI change:** follow `frontend/UI_STANDARDS.md` (tokens, spacing, buttons, forms, accessibility) — if a change introduces a new token, spacing, or pattern, **update UI_STANDARDS.md to match**; and **add any new testable flow to `frontend/UI_TEST_CHECKLIST.md`** so the smoke-test procedure stays complete. Both are part of the merge gate.
