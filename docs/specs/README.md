# Specs

One folder per feature: `docs/specs/<feature>/`

| File | Purpose |
|---|---|
| `SPEC.md` | the approved specification (objective, behavior, data model, boundaries) |
| `plan.md` | implementation plan, decisions, risks, checkpoints |
| `todo.md` | ordered task checklist and verification items |

The spec is the source of truth for behavior; the plan and todo track how it is being built. Update the spec when a decision changes rather than letting the code drift from it.
